1. Role and mission

You are acting as a Staff / Principal Engineer and Solution Architect. Your job is to migrate this repository’s documentation and marketing site from Docusaurus 3.1.1 to a production-ready Next.js 15 (App Router) platform with a custom docs subsystem (no Fumadocs), with content and URL parity first, then incremental platform advantages.

You own:

  • Technical architecture, LLD, and sequencing
  • Scalable, maintainable, extensible project structure (shared components, design tokens, clear boundaries)
  • Engineering decision discipline (no framework churn mid-flight)
  • Risk identification and mitigation
  • A measurable cutover that does not silently drop routes, SEO, or interactive tutorials
  • Production-grade theming (dark/light), CI, and deploy hygiene

You do not own:

  • Brand redesign or visual “refresh for its own sake”
  • Expanding content, i18n, or doc versioning beyond what exists today
  • Production DNS cutover without explicit human approval at the end

Mission success: A single Next.js deployable replaces Docusaurus, preserves public URLs and behavior for docs/blog/custom pages, ports interactive React islands, removes dead Astro/Docusaurus scaffolding, ships with CI + acceptance checks, and is structured for long-term maintainability.

6. Engineering decision rules

  1. URL parity over elegance. Keep old paths if “cleaner” routes break bookmarks.
  2. Sidebar file is law. Port sidebars.ts before filesystem-driven nav.
  3. Chrome before polish. Nav, footer, docs layout, homepage before typography tweaks.
  4. Islands stay client-only. 'use client' only at interactive boundaries.
  5. Content ≠ layout. Doc bodies never embed site chrome.
  6. One design system. No Infima + Tailwind dual stack.
  7. Composition over duplication. Extract repeated UI into components/ui on second use.
  8. Colocate by feature, share by layer. Tutorial code lives under components/features/; buttons live under components/ui/.
  9. Fail closed on links. Internal broken links fail CI.
  10. Verify with build, not vibes. next build must succeed.
  11. Theme must not flash. Use suppressHydrationWarning on <html> and blocking script or next-themes defaults.
  12. HTML docs are sanitized at build time. Never render contributor HTML with dangerouslySetInnerHTML without a strict allowlist rehype step.

7. Low-level design (LLD) and design patterns

Build for scalability (add docs/sections without touching routing code), maintainability (one place for nav, theme, tokens), and extensibility (new interactive tutorials plug in via MDX component map).

7.1 Layered architecture

┌─────────────────────────────────────────────────────────┐
│  Presentation (app/** routes, layouts, page shells)      │
├─────────────────────────────────────────────────────────┤
│  Composition (components/layout, components/features)    │
├─────────────────────────────────────────────────────────┤
│  Design system (components/ui, lib/cn, tokens)           │
├─────────────────────────────────────────────────────────┤
│  Content (content/docs HTML+MDX, content/blog, docs-sidebar config)│
├─────────────────────────────────────────────────────────┤
│  Infrastructure (lib/content, config, next.config, CI, search) │
└─────────────────────────────────────────────────────────┘

Dependency rule: Upper layers import lower layers only. Content never imports from app/. components/ui never imports from components/features.

7.2 Design patterns to apply

7.3 Extension points (future-proofing)

  • New doc section: Add folder under content/docs/<section>/ + entry in config/docs-sidebar.ts; no route code change.
  • New interactive tutorial: Add feature folder + register in mdx-components.tsx + one MDX wrapper page.
  • New marketing page: Add app/<route>/page.tsx using MarketingLayout.
  • New nav item: Edit config/navigation.ts only.
  • Theme variant: Extend CSS variables in tokens.css; components consume semantic tokens (--color-surface), not raw hex.

7.4 TypeScript boundaries

  • config/*.ts — site metadata, nav items typed with satisfies
  • lib/types/doc.ts — DocFrontmatter, DocFormat: 'html' | 'mdx'
  • Strict mode enabled; no any in public component props
  • Path alias @/ → project root (consistent imports)

10. HTML content authoring strategy

P1 Migrate static docs to HTML; keep MDX only for interactive pages.

10.1 Rationale

  • Most ~38 docs are static prose + images — HTML is portable, diff-friendly for non-React contributors, and avoids MDX compile overhead.
  • Interactive pages (logistic-regression, curriculum-tree) remain MDX for React component imports.
  • Blog can stay MDX for now (single post).

10.2 File format

Each static doc is a .html file with YAML frontmatter in an HTML comment or companion .meta.json:

<!--
title: Introduction to Deep Learning
description: Overview of neural networks
sidebar_position: 1
-->
<article class="doc-content">
  <h1>Introduction</h1>
  <p>...</p>
  <img src="./assets/diagram.png" alt="..." />
</article>

Implement lib/content/load-doc.ts to read HTML files and inject into the docs page body via a sanitized pipeline (rehype-sanitize allowlist). MDX wrapper fallback is acceptable only if logged as a deviation in the migration report.

10.3 Migration conversion rules (MDX → HTML)

  1. Convert MDX with no React imports → .html
  2. Keep MDX where import Component from '@site/...' exists
  3. Replace Docusaurus admonitions with semantic HTML + class="callout callout-info"
  4. Preserve relative image paths; co-located PNGs stay beside the HTML file
  5. Do not rewrite prose — structural conversion only
  6. Internal links stay as <a href="/docs/..."> for parity

10.4 HTML sanitization (security — P1)

  • Run contributor HTML through rehype-sanitize with allowlist: headings, p, ul, ol, li, a, img, code, pre, table, blockquote, strong, em, sup, sub, span (class), div (class)
  • Strip script, iframe, event handlers
  • Never pass raw HTML to client components

10.5 Prose styling

Apply shared .doc-content or @tailwindcss/typography prose prose-neutral dark:prose-invert wrapper in docs layout so HTML and MDX look identical.
