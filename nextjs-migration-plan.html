2 Pros & Cons of Next.js

Pros

Unified React stack

One framework for docs, marketing (/fellowship), and future product pages.

Pros

Vercel-native deploy

Fast PR previews, edge CDN, simple CI/CD pipeline.

Pros

Future flexibility

Easy path to auth, API routes, dashboards, user progress sync.

Pros

Modern DX

App Router, RSC, strong TypeScript integration, Fumadocs/Nextra ecosystem.

Cons

Lost Docusaurus features

Sidebar, prev/next, edit links, blog tags — must rebuild or use a docs framework.

Cons

High layout work

Infima theme doesn't port; navbar/footer/docs chrome ≈ 30–40% of effort.

Cons

MDX migration risk

39 files with KaTeX + embedded React need page-by-page validation.

Cons

No immediate user gain

Site works today — migration is engineering investment, not a feature launch.

4 Phased Migration Plan

Seven phases, ~3–4 weeks for one developer (+ 1 week buffer for MDX edge cases).

Phase 0 — Cleanup 1 day
  • Decisions — locked (see above)
  • Remove Astro leftovers, unused components
  • Add build/ to .gitignore
  • Inventory all /docs/* URLs for redirect QA
Clean repo + URL inventory
Phase 1 — Next.js Scaffold 2–3 days
  • Create Next.js 15 (App Router, TypeScript, default Tailwind)
  • Default layout shell — simple header/footer (no Infima)
  • Defer hosting/deploy config until Phase 6
  • CI: build on PR + preview deploy
Live preview with shell layout
Phase 2 — Marketing Pages 2–3 days
  • Migrate /, /fellowship, /contribute
  • Restyle with default Tailwind — content over pixel-perfect match
3 routes live
Phase 3 — Docs Infrastructure 5–7 days — largest phase
  • MDX pipeline (@next/mdx + KaTeX plugins)
  • Docs layout: sidebar + /docs/[...slug] catch-all route
  • Port sidebars.ts navigation
  • Configure KaTeX + syntax highlighting (Shiki)
  • Migrate all 39 MDX files preserving slugs
  • Register MDX components (CurriculumTree, tutorials)
  • Sitemap only — no doc search at launch
All doc routes render with sidebar
Phase 4 — Interactive Components 3–4 days
  • Mark canvas components with 'use client'
  • Test CurriculumTree + localStorage hydration
  • Validate KaTeX on heaviest math pages
  • Cross-browser testing
Tutorials behave like today
Phase 5 — Blog Skipped — revisit later
  • Deferred: migrate blog or add /blog redirect
  • Only 1 post today — not blocking launch
Out of scope until you revisit
Phase 6 — SEO, Redirects & Cutover 2–3 days
  • URL map + 301 redirects for every old path
  • Match meta, OG image, canonical URLs
  • Choose hosting + domain (deferred until here)
  • DNS cutover with rollback plan
Production on Next.js, zero SEO regression
Phase 7 — Post-Launch Ongoing
  • Update contributor docs
  • Add Playwright smoke tests
  • Monitor 404s for 2 weeks
  • Decommission Docusaurus deploy
Stable production site
